# 🔪 GBK-To-UTF8-Recursive (乱码杀手)

### 告别满屏“锟斤拷”与“烫烫烫”，让代码重见天日。

## 📖 项目简介 (Description)

你是否在打开十年前的 C 语言工程、或者从网上下载的源码包（尤其是教学例程、单片机源码）时，遇到过这种情况：
本来应该是中文注释的地方，变成了一串神秘的字符 —— **“锟斤拷锟斤拷锟斤拷”**？

这是经典的编码灾难。本项目旨在拯救你的眼睛和心态。

这是一个轻量级、零依赖的 Python 工具，专门用于批量处理 **GBK/GB2312** 编码的老旧代码文件。它不仅能将它们批量“洗”成现代通用的 **UTF-8**，还能**完美保留原有的文件夹层级结构**。

## ✨ 核心特性 (Features)

* **递归扫描**：自动深入遍历 `input` 文件夹下的所有子目录，无论藏得多深的文件都能被找到。
* **智能镜像**：在 `output` 和 `backup` 中自动重建与源文件夹完全一致的目录结构。
* **非破坏性**：拒绝危险操作！原文件会被移动到 `backup` 目录存档，转换后的新文件生成在 `output` 目录。
* **自动容错**：如果文件已经是 UTF-8 或者是图片、二进制文件，脚本会跳过转码并直接复制，防止文件损坏。

## 📂 项目结构 (Structure)

在使用前，请确保你的目录结构如下所示：

```text
Project_Root/
├── input/           <-- [入口] 这里放入你需要转换的文件夹或文件（如：Old_Project/）
├── output/          <-- [出口] 转换好的 UTF-8 文件会出现在这里，结构与 input 一致
├── backup/          <-- [仓库] 处理完的原文件会被移动到这里备份
└── gbk_converter.py <-- [核心] Python 脚本文件
```

- **input**: 待处理的“乱码”源文件存放区。
- **output**: 处理完成的“干净”文件存放区（可以直接拿去用）。
- **backup**: 原始文件备份区（如果转换出问题，可以从这里找回）。

## 🚀 使用方法 (Usage)

1. **准备文件**： 将你所有需要转换的 C 语言文件（或者整个工程文件夹）复制到 `input` 文件夹中。

2. **运行程序**： 在当前目录下打开终端（Terminal）或 PowerShell，运行以下命令：

   Bash

   ```
   python gbk_converter.py
   ```

   *如果你使用 VS Code，也可以直接打开 `gbk_converter.py` 并点击右上角的运行按钮。*

3. **查看结果**：

   - 控制台会显示处理进度。
   - 完成后，去 `output` 文件夹查看转换后的代码。
   - 去 `backup` 文件夹确认原文件是否已归档。

## ⚠️ 注意事项 (Notes)

- **针对 GB 系列编码**： 本项目专为 **GBK** 和 **GB2312** 编码设计（这是国内老旧 C 代码最常见的编码）。
- **兼容性警告**： 如果你的文件是 Big5（繁体中文）或 Shift-JIS（日文）编码，本脚本可能会报错或转换失败。虽然脚本包含错误跳过机制，但建议仅用于处理 GBK 编码文件。
- **文件安全**： 脚本**不会删除**你的文件，只会**移动**文件。所有放入 `input` 的文件最终都会在 `backup` 中找到。

## 🛠 运行环境 (Environment)

- **操作系统**：Windows / macOS / Linux (推荐在 Windows 下处理 GBK 文件)
- **Python 版本**：Python 3.0 及以上
- **编辑器**：VS Code, PyCharm, 或任意支持 Python 的终端
- **依赖库**：无（基于 Python 标准库 `os` 和 `shutil` 开发，无需 `pip install`）

------

> **关于“锟斤拷”的小科普**： 当 UTF-8 的替换字符（）被错误地用 GBK 编码解码时，就会显示为“锟斤拷”。希望这个工具能帮你彻底消灭它们！
